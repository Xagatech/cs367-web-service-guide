REST คืออะไร

Representational State Transfer — สถาปัตยกรรมสำหรับ web services โดย Roy Fielding ปี 2000 (วิทยานิพนธ์ปริญญาเอก) ไม่ใช่ protocol แต่เป็น architectural style

ROA คืออะไร

Resource-Oriented Architecture — แนวทางออกแบบ API โดยเน้น resources เป็นศูนย์กลาง มี 4 คุณสมบัติหลัก

3 สถาปัตยกรรม: REST vs RPC vs Hybrid
Styleแนวคิดตัวอย่างข้อสังเกต
RESTResource-based, nounsGET /users/1มาตรฐานสากล
RPC-styleAction-based, verbsPOST /getUserง่ายแต่ไม่เป็นมาตรฐาน
REST-RPC HybridผสมPOST /users/1/activateใช้เมื่อ action ไม่ match CRUD
ROA 4 คุณสมบัติหลัก
1. Addressability

ทุก resource มี URI เฉพาะของตัวเอง

/students/12345
/courses/CS367/enrollments
/students/12345/grades
2. Statelessness

Server ไม่เก็บ state ของ client — ทุก request ต้องพกข้อมูลครบ (เช่น JWT token) ใน header

3. Connectedness (HATEOAS)

Response มี links บอกว่าทำอะไรต่อได้บ้าง

{
  "id": 1,
  "links": {
    "self": "/students/1",
    "courses": "/students/1/courses",
    "grades": "/students/1/grades"
  }
}
4. Uniform Interface

ใช้ HTTP methods ตามความหมายมาตรฐาน ไม่คิดเอง — GET=read, POST=create, PUT=replace, DELETE=delete

URI Design Rules

Timeout & Retry (Exponential Backoff + Jitter)
Timeout

กำหนดเวลาสูงสุดรอ response — ถ้าเกิน fail fast แทนรอไม่รู้จบ ต้องตั้งกับทุก external call

Retry + Exponential Backoff
attempt 1: wait 1s
attempt 2: wait 2s
attempt 3: wait 4s
attempt 4: wait 8s
+ random jitter (แต่ละ attempt)

Jitter = ป้องกัน thundering herd (ทุก client retry พร้อมกัน)
ใช้กับ transient errors เท่านั้น — ห้าม retry validation errors

Circuit Breaker — 3 States
🟢 Closed
Traffic ผ่านปกติ — นับ failures ต่อเนื่อง ถ้าเกิน threshold → เปิด Open
🔴 Open
Block ทุก request ทันที (fast fail) ไม่ส่งไปที่ service — รอ timeout แล้วไป Half-Open
🟡 Half-Open
ปล่อย 1 request ทดสอบ — สำเร็จ → Closed, ล้มเหลว → กลับ Open

gRPC คืออะไร

Google Remote Procedure Call — เรียก function บน server อีกเครื่องเหมือนเรียก local function สร้างโดย Google ใช้ HTTP/2 + Protocol Buffers

Technology Stack
  • HTTP/2 — Multiplexing, binary protocol, header compression, server push
  • Protocol Buffers (Protobuf) — Binary serialization ~3-10x เล็กกว่า JSON, เร็วกว่า parse
.proto File — ไฟล์นิยาม API 
syntax = "proto3";         // version ของ protobuf

package student;           // namespace

// Service definition — บอกว่ามี RPC อะไรบ้าง
service StudentService {
  rpc GetStudent (StudentRequest) returns (StudentResponse);
  rpc ListStudents (ListRequest) returns (stream StudentResponse);  // server streaming
  rpc CreateStudents (stream StudentRequest) returns (StudentResponse);  // client streaming
  rpc Chat (stream ChatMsg) returns (stream ChatMsg);              // bidirectional
}

// Message definitions — structure ของ data
message StudentRequest {
  int32 id = 1;            // field number (ไม่ใช่ value!)
}

message StudentResponse {
  int32 id = 1;
  string name = 2;
  string major = 3;
  string email = 4;
}

message ListRequest {
  string department = 1;
}
Field Numbers — สำคัญมาก!

Protobuf ใช้ field number (= 1, = 2) ใน binary encoding ไม่ใช่ field name — ดังนั้น เปลี่ยน number = breaking change ที่ทำให้ existing clients อ่าน data ผิด แต่เปลี่ยนชื่อ field ได้ (backward compatible)

2. Prometheus Middleware

รัน before/after ทุก handler — บันทึก metric อัตโนมัติ

func prometheusMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        c.Next()  // เรียก handler จริง
        duration := time.Since(start).Seconds()
        status := fmt.Sprintf("%d", c.Writer.Status())

        // บันทึก metrics
        httpRequestsTotal.WithLabelValues(
            c.Request.Method, c.FullPath(), status,
        ).Inc()
        httpRequestDuration.WithLabelValues(
            c.Request.Method, c.FullPath(),
        ).Observe(duration)
    }
}

4. Graceful Shutdown

รับ SIGTERM จาก K8s → drain connections ก่อน exit

// Start server in background goroutine
go func() {
    if err := srv.ListenAndServe(); err != nil {

}()

// Block รอ signal SIGTERM หรือ SIGINT
quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit  // หยุดตรงนี้จนกว่าจะได้รับ signal

// Graceful shutdown — รอ max 15 วินาที
ctx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
defer cancel()
srv.Shutdown(ctx)  // รอ in-flight requests เสร็จก่อน

ทำไม Multi-stage?
  • Stage 1: มี Go compiler, tools ทั้งหมด → ไม่ต้องใส่ใน final image
  • Stage 2: copy แค่ binary เดียว → image เล็ก, attack surface น้อย
  • scratch = empty image ไม่มี shell, ไม่มี OS utilities

Step 3 — proto/student.proto อธิบายทุกบรรทัด 
syntax = "proto3";              // ใช้ proto version 3

package student;               // namespace ป้องกัน name collision

option go_package = "./studentpb";  // บอก protoc ว่าจะ generate code ไว้ที่ไหน

// Service = กำหนด RPC methods ที่ server ต้อง implement
service StudentService {
  rpc GetStudent (StudentRequest) returns (StudentResponse);

  // assignments เพิ่มเติม:
  rpc ListStudents (Empty) returns (StudentListResponse);
  rpc CreateStudent (StudentListResponse) returns (Empty);
  rpc DeleteStudent (DeleteStudentRequest) returns (Empty);
}

// Messages = structure ของ data (เหมือน struct)
message Empty {}               // ไม่มี payload (เช่น void)

message StudentRequest {
  int32 id = 1;                // field number 1 (ใช้ใน binary encoding)
  optional string name = 2;   // optional field
}

message StudentResponse {
  int32 id = 1;
  string name = 2;
  string major = 3;
  string email = 4;
  // ถ้าเพิ่ม field ใหม่ → ต้องใช้ field number ใหม่ (5, 6, ...)
  // ห้ามเปลี่ยน field number เดิม = breaking change!
}

message StudentListResponse {
  repeated StudentResponse student = 1;  // repeated = array
}

message DeleteStudentRequest {
  string name = 1;
}

package main

import (
    "context"
    "log"
    "net"

    pb "grpc-student/studentpb"   // import generated code
    "google.golang.org/grpc"
)

// server struct — ต้อง embed UnimplementedStudentServiceServer
// เพื่อ forward-compatibility (ถ้า proto เพิ่ม method ใหม่ ไม่ compile error)
type server struct {
    pb.UnimplementedStudentServiceServer
}

// Implement GetStudent RPC method
// signature ต้องตรงกับที่ proto กำหนด
func (s *server) GetStudent(ctx context.Context, req *pb.StudentRequest) (*pb.StudentResponse, error) {
    log.Printf("Received request for student ID: %d", req.Id)

    // ตรงนี้ปกติจะ query DB แต่ lab ใช้ mock data
    return &pb.StudentResponse{
        Id:    req.Id,
        Name:  "Alice Johnson",
        Major: "Computer Science",
        Email: "alice@university.com",
    }, nil
}

func main() {
    // เปิด TCP listener บน port 50051
    lis, err := net.Listen("tcp", ":50051")
    if err != nil {
        log.Fatalf("Failed to listen: %v", err)
    }

    // สร้าง gRPC server
    grpcServer := grpc.NewServer()

    // Register service implementation
    pb.RegisterStudentServiceServer(grpcServer, &server{})

    log.Println("gRPC Server running on port 50051")
    // เริ่ม serve (blocking)
    grpcServer.Serve(lis)
}

Step 6 — client/client.go อธิบายทุกส่วน 
package main

import (
    "context"
    "log"
    "time"

    pb "grpc-student/studentpb"
    "google.golang.org/grpc"
)

func main() {
    // เชื่อมต่อ gRPC server
    // grpc.WithInsecure() = ไม่ใช้ TLS (สำหรับ dev/lab เท่านั้น)
    conn, err := grpc.Dial("localhost:50051", grpc.WithInsecure())
    if err != nil {
        log.Fatalf("Could not connect: %v", err)
    }
    defer conn.Close()

    // สร้าง client stub (generated โดย protoc)
    // stub คือ wrapper ที่ทำให้เรียก remote method เหมือน local function
    client := pb.NewStudentServiceClient(conn)

    // Context with timeout — ถ้า server ตอบไม่ทัน 1 วินาที → error
    ctx, cancel := context.WithTimeout(context.Background(), time.Second)
    defer cancel()

    // เรียก RPC — เหมือนเรียก local function ธรรมดา
    res, err := client.GetStudent(ctx, &pb.StudentRequest{
        Id: 101,
    })
    if err != nil {
        log.Fatalf("Error calling GetStudent: %v", err)
    }

    log.Printf("Student Info:")
    log.Printf("ID: %d", res.Id)
    log.Printf("Name: %s", res.Name)
    log.Printf("Major: %s", res.Major)
    log.Printf("Email: %s", res.Email)
}

go run client/client.go
